# Бурундук

Локально запускаемый мессенджер с аккаунтами, личными сообщениями по WebSocket и аудио-/видеозвонками WebRTC. В базе нет тестовых пользователей: контакты появляются только после регистрации реальных аккаунтов и добавления по никнейму.

## Запуск

Нужен Node.js 20 или новее.

```sh
npm install
npm start
```

Откройте `http://localhost:3000`. Для проверки общения создайте два аккаунта в разных браузерах или профилях, затем добавьте точный никнейм второго пользователя в контакты.

Пользователи и история сообщений хранятся в `data/messenger.json`. Пароли хранятся в виде хешей scrypt. Токены входа действуют до перезапуска сервера.

В профиле можно выбрать животное-эмодзи для аватара и заполнить короткое описание до 160 символов. Эти данные сохраняются на сервере и видны участникам общих групп.

## Группы

Создавайте группы из своих контактов (до 50 участников), меняйте название, описание и значок, добавляйте и удаляйте участников, передавайте владение или удаляйте группу. Владелец также может закрепить одно сообщение. В группах доступны ответы, реакции, упоминания `@username` с уведомлением участнику и поиск по загруженной истории. Фото и видео пока отправляются только в личных чатах.

Групповые аудио- и видеозвонки используют WebRTC mesh: сервер передаёт только сигнализацию, а медиа направляется напрямую между участниками (либо через TURN, если сеть не позволяет прямое соединение). В одном звонке может быть до 6 человек; пропускная способность и качество при этом зависят от устройств и сети каждого участника. Push о групповом звонке — приглашение открыть группу, а не работающий в фоне звонок.

## Фото, видео и сообщения

Фото и видео размером до 50 МБ передаются между браузерами по WebRTC DataChannel небольшими блоками. На сервер уходят только сигнализация соединения и метаданные сообщения — содержимое файла не загружается на сервер и не хранится в `data/messenger.json`. Оба собеседника должны быть онлайн, а страницу нельзя закрывать до завершения передачи. При сложной конфигурации NAT прямому соединению может понадобиться TURN; в этом случае трафик проходит через настроенный TURN-сервер, но не через сервер Бурундука.

Полученные и отправленные файлы хранятся локально в IndexedDB браузера. Поэтому историю файлов нельзя восстановить на новом устройстве или после очистки данных браузера; для получения файла получатель должен быть подключён во время передачи. Сообщения поддерживают ответы и реакции 👍 ❤️ 😂 😮 😢 👏.

## Уведомления и звук

Новые сообщения и входящие звонки показывают уведомление в приложении. Для сообщений и приглашений на звонок поддерживаются системные Web Push-уведомления, в том числе когда приложение закрыто. Push группируются по чату и открывают нужную переписку по нажатию; если приложение открыто и видно, системный баннер не дублирует уведомление внутри приложения. Нажатие на push о звонке открывает чат для обратного вызова: ответить на звонок и продолжить WebRTC-разговор можно только когда приложение открыто и подключено. Кнопка «Уведомления» запрашивает разрешение и подключает устройство; выключение удаляет его push-подписку. В быстрых настройках звук и вибрацию можно включать и выключать отдельно; в «Мелодиях» доступны три варианта для сообщений и три для звонков, каждый можно прослушать. Настройка вибрации сохраняется для каждого push-устройства. Вибрация зависит от поддержки браузера и устройства; мелодии проигрываются в открытом приложении, а звук фонового push контролируется браузером и ОС. Звук браузера разблокируется первым действием пользователя.

Для системных и фоновых уведомлений сервер должен быть доступен по HTTPS, работать постоянно и иметь доступ к push-сервисам браузера. На телефоне `localhost` на компьютере не подходит: нужен HTTPS-адрес. Разрешите уведомления в настройках сайта; если браузер уже блокировал их, измените разрешение вручную и снова включите уведомления в приложении. Если Service Worker не запускается, закройте лишние вкладки сайта; в Chrome/Edge откройте DevTools → Application → Service Workers → Unregister, обновите страницу и настройте уведомления повторно. VAPID-ключи создаются автоматически и хранятся в `data/vapid-keys.json`; сохраните этот файл при переносе сервера и не публикуйте его. Для production задайте `VAPID_SUBJECT` в формате `mailto:адрес-оператора@example.com`.

На Android откройте HTTPS-адрес в Chrome, разрешите уведомления и при желании добавьте сайт на главный экран через меню браузера. На iPhone/iPad Web Push доступен в iOS 16.4+ для сайта, добавленного на экран «Домой» и запущенного как веб-приложение. Push о звонке — это баннер-приглашение, а не работающий в фоне звонок: чтобы поговорить, откройте чат и перезвоните.

## Звонки и публикация

Звонки передают сигнал WebRTC через WebSocket и соединяют браузеры напрямую. Доступ к микрофону и камере требует `localhost` или HTTPS. STUN помогает установить соединение; для сетей, где прямое соединение невозможно, задайте TURN-сервер:

- `TURN_URL` — адрес TURN-сервера;
- `TURN_USERNAME` — имя пользователя;
- `TURN_CREDENTIAL` — пароль или выданные провайдером учётные данные.

Для доступа из интернета разверните сервер за HTTPS/WSS reverse proxy и настройте TURN. Не публикуйте сервер с HTTP в открытом интернете: для production также потребуются HTTPS, резервное копирование, ограничение частоты запросов и управляемое хранилище.

Сообщения в этой версии не имеют сквозного шифрования: сервер может их прочитать.
